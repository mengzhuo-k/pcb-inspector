# 焊视 · PCB 焊接质量检测

本机研发验证系统。Windows 上双击 `start.cmd`，打开 http://127.0.0.1:8765 。检测与模型训练通过同一个服务启动。顶部“模型训练”打开独立训练平台 `/platform`，员工按“选产品 → 拍照/上传 → 框缺陷 → 保存”使用，后台再走数据集、训练、评估、注册、发布、反馈。首次在新电脑运行需安装 Python 3.11，并联网安装依赖。

系统同时运行两个模型：

- 单类别目标检测模型（`missing_connection`）定位孔位/焊盘的漏焊候选；
- 七类图像级分类模型（SMD DefDB）识别整板主要焊接缺陷类型：虚焊/冷焊、桥接、多锡、焊盘/元件损伤、元件偏移、缺件与合格。数据集只提供图像级标签，没有缺陷框，因此分类结果只给类型、不定位到具体元件。

任一模型判定不合格即初判该图不合格，员工仍需对照原图复核并可在复查页补标缺陷类型。

## 模型训练平台（/platform）

平台是独立的 Flask 应用，挂载在 `/platform`，数据库与图片、权重放在 `data/platform`（可用 `PCB_PLATFORM_DATA` 指定）。它把训练拆成九个可重复的环节：

1. **项目**：一个项目对应一个板型/工位，所有图片、数据集、模型按项目隔离。
2. **采集/上传**：登记批次和板序列号；图片原图入库并计算 SHA-256。
3. **标注**：在图上拖框，选择缺陷类别；同一张图可多个框。员工只需在图上框缺陷并选类型，不再填写整板类型。
4. **保存入库**：框完点“保存并继续”即写入，不需要复核；平台自动标记为已保存，可直接进入训练数据。界面不再提供“检查标注”入口。
5. **数据集版本**：按板序列号/批次/随机分组切分训练、验证、测试，同一块板的图片不会跨集合；平台给出数量、类别分布和分组告警。
6. **训练**：两个模板——`det` 多类别缺陷检测（YOLO 检测，输出框和类型）、`cls` 整板分类（YOLO 分类）。任务在后台子进程运行，页面可实时看日志。
7. **评估**：检测模板记录 mAP50、mAP 和每类 P/R/AP；分类模板记录 top1/top5 和混淆矩阵。
8. **模型注册与导出**：训练完成自动生成版本（v1、v2…）、权重 SHA-256、模型卡和指标；“模型版本”页可导出训练模型 zip（`weights/best.pt`、`model_card.json`、`classes.txt`、`labels.json`、`README.txt`），也可只下载权重。

标注页不依赖孔位/焊盘自动定位，全部缺陷由员工手动圈出：先在左上角选缺陷类型，再拖动鼠标画框；实线 = 已标记缺陷，颜色随类型；画错右键取消。

8.5 **一键生成并启用**：“模型版本”页可直接把当前项目已保存的缺陷框自动做成训练集、训练、注册并发布；检测端约 3 秒内自动加载，不需要手工导出或发布。

9. **发布与监控**：发布到工位后，检测端优先加载该多类别检测模型；平台记录部署版本，并支持把现场误判/低置信图片上传到反馈队列，转成待标注样本回流。

首页和“准确率”页会直接列出**每一类缺陷的判断准确率**：读取当前已发布模型的验证集指标；没有平台模型时，退回本机 `models/smd_defect_cls_v1.json` 的 SMD DefDB 参考指标，并明确标注“参考模型”。检测模型的“准确率”用该类召回率（检出率）表示；分类模型用混淆矩阵计算该类准确率与报出后正确率。员工按这张表决定哪些类型可以放心用、哪些必须多复核。员工界面只保留首页、拍照/上传、框缺陷、准确率、模型版本、使用情况；框完点保存即入库，没有检查标注环节；**训练数据和训练模型入口已从界面移除**，训练仍可通过平台 API（`/api/projects/<id>/datasets`、`/api/datasets/<id>/train`）或脚本执行。

检测端集成：`app.py` 增加 `PlatformRuntime`，每 3 秒读取 `data/platform/platform.sqlite` 中已激活的 `det` 模型；有平台模型时优先使用多类别检测，无平台模型时回退旧单类漏焊模型。`/api/model/status` 的 `platform` 字段显示平台模型状态。

旧 `/training` 页面仍保留，用于固定板型、单类别漏焊的快速标注训练；新项目建议直接用 `/platform`。平台核心接口和回归测试见 `tests/test_platform.py`。

## 检验流程

工作空间按四个入口使用。

- “导入图片”只用于填写工位、批次和选择图片，提交后进入该批次处理详情。
- “检测批次”默认列出正在导入、后台检测、待提交复查和待手动导出的批次。点开后可查看进度、继续上传、重试失败图片、查看逐图结果以及安排合格图片抽样；通过“已完成”筛选可回看已导出报告的批次。
- “不合格复查”集中列出已提交批次中当前判定不合格的图片，以批次名称、导入序号和文件名定位。支持筛选批次与未复查图片，改判为合格后会退出不合格列表；页内提供待导出批次的手动报告导出按钮。
- “批次记录”按批次展示，每批显示图片总数、合格数、不合格数、检测状态和合格率，点开查看逐图记录。早期逐图记录按工位和批次名称归组。合格率按合格图片数 / 已成功检测并判定图片数计算，失败项单独显示。

打开“导入图片”，填写工位与批次，一次选择最多 200 张图片并导入。图片逐张上传，后台队列逐张检测，进度与结果自动刷新。机器检出漏焊候选即初判不合格，未检出即初判合格。损坏或检测失败的图片单独显示并排除在合格率分母之外，可继续上传或重试。刷新页面后可选择已有批次继续查看，未完成导入时选择该批次完整的原始图片即可继续。

“机器初判合格率”按机器初判合格数 / 成功检测图片数计算。“当前合格率”按当前结论为合格的图片数 / 成功检测图片数计算，员工改判后同步更新。不合格图片使用红框并优先显示。点击任意已完成图片进入复查，填写员工姓名并保存，可反复修改，系统保留复查记录。多人同时改同一张图片时，会提示重新打开以避免覆盖他人的修改。

图片检测结束后，批次显示“待提交复查”，继续留在正在处理列表。点击“提交不合格复查”后，不合格图片序号进入复查页，批次显示“待手动导出”。员工手动点击“导出报告并完成批次”，浏览器取得 PDF 报告文件后才记录完成时间。尚有图片待上传、排队或正在检测时，暂时无法提交。批次详情会汇总整板识别出的缺陷类型及张数。

报告包含批次信息、合格率、不合格图片序号清单、逐图结果、检测模型及员工复查意见。检测失败项单列。报告生成或下载失败时，批次仍待导出。导出期间若检验结果变化，会提示重新导出。完成后再次修改结论或删除图片，批次重新进入待导出状态，已有报告作为当时结果的快照保留。浏览器接收文件并发起保存下载后，系统确认完成；本地保存对话框是否被取消取决于浏览器，系统无法读取员工电脑的保存结果。

抽样范围限定为机器初判合格的图片，默认随机抽取 10%（向上取整），也可指定张数。图片检测结束后即可抽样，报告导出前后均可进行。抽样清单显示本轮已复查进度。重新抽样会替换当前清单，已存在的复查记录保留，新一轮需要重新复查。

1. 上传 PCB 照片，或使用自带的漏焊样例。允许摄像头访问后，可连续查看带候选框的检测画面。实际刷新率取决于摄像头与推理硬件。
2. 在图像右侧填写工位、生产批次，可展开现场备注。语音按钮调用浏览器的中文语音识别，支持情况与联网要求取决于浏览器。
3. 点击“检测缺陷并建档”。连续采集时，系统对点击时捕获的帧重新推理并保存。点位序号与置信度显示在图像外，点击条目显示对应引导线。可关闭标注查看原图或全屏查看。右侧“整板识别”显示缺陷类型、置信度、缺陷概率与判定阈值，并列出次选类别。
4. 复核候选，对照应焊孔位与焊盘确认有无漏焊，再选择当前结论并输入姓名保存。支持重新复查，历史记录可按批次、工位或结论检索。复查页可勾选补标缺陷类型（漏焊、虚焊、冷焊、桥接、多锡、焊盘损伤、元件偏移、缺件、氧化、烧伤）。
5. 在最近检验、检验记录或详情中点击删除并确认，可删除一份检验单，包括其图像、检测结果和签核信息。统计会同步更新。

## 检测与分析

识别端自动读取训练库中最新完成的版本，校验类别并试运行成功后切换。检查周期约 3 秒，新模型加载期间使用当前可用版本，加载失败时在顶部提示并继续使用可用版本。训练中的检查点与失败训练不会用于检测。默认训练库为 `data/learning`，可通过 `PCB_TRAIN_DATA` 指定。无可用训练版本时使用随项目提供的 v7 权重。

后续图片使用切换后的模型，包括正在处理批次中的后续图片。每张新检验单均记录实际使用的版本与权重 SHA-256，已检测结果保留原版本来源。顶部显示当前检测模型，训练版本列表标记“检测正在使用”。`start-training.cmd` 也会打开同一系统的训练页。

推理输入尺度为 960，置信度阈值为 0.25，输出 `missing_connection` 类别并显示为“疑似漏焊”。该模型定位漏焊候选，检验员需对照应焊点位复核。未检出候选时仍需人工确认，换板型及现场精度需要独立验证。既有多类别历史检验单保留当时的检测结果。

### 整板缺陷识别（SMD DefDB）

分类模型权重与模型卡为 `models/smd_defect_cls_v1.pt` 和 `models/smd_defect_cls_v1.json`，可用 `PCB_DEFECT_WEIGHTS`、`PCB_DEFECT_CARD`、`PCB_DEFECT_THRESHOLD` 覆盖。模型在启动时加载，替换权重后需重启服务；加载失败时顶部提示，漏焊检测不受影响。

七类映射为 `damaged_component` 焊盘/元件损伤、`excess_solder` 多锡、`good_solder` 未见明显缺陷、`misaligned_component` 元件偏移、`missing_component` 缺件、`poor_solder` 虚焊/冷焊、`solder_bridge` 桥接。数据集没有单独的“冷焊”标签，因此虚焊与冷焊合并显示；复查页可人工补标区分。

判定规则：Top-1 为缺陷类且 `1 - P(good_solder)` 达到模型卡阈值（默认 0.5）时初判不合格。阈值在独立测试集上按“精确率不低于 0.85、尽量提高召回”选出，所以该测试集同时承担阈值校准，指标偏乐观；换板型、换工位后需要用新样本重新验证。分类只给缺陷类型，不定位具体元件，整板照片中的细微缺陷仍可能漏判。

数据集为 Zenodo SMD DefDB（DOI `10.5281/zenodo.20001570`，CC BY 4.0）：1190 张、7 类各 170 张，由 119 张原图增强而来。训练/验证/测试按“10 张增强图为一组、重复组先合并”的方式 810/140/240 划分，避免同一原图的增强副本跨集合泄漏。独立测试的 top1/top5、各类召回率、混淆矩阵和判定阈值记录在模型卡中。数据规模与板型有限，指标不代表新产线精度。

训练脚本：`training/fetch_smd_defdb.py`（下载校验）、`training/prepare_smd_defdb.py`（分组划分）、`training/train_smd_classifier.py`（训练、测试与模型卡生成）。魔搭 8 核 CPU 一键脚本见 `training/modelscope/`。

根因提示来自类别对应的排查规则。系统统计同工位最近 50 条不合格检验单中的同类候选数，并在双方均有温度数据时比较峰值与历史均值。历史关联和图像候选均需现场验证。自动结论依据当前模型的候选检出结果，现场精度需要用独立标注样本验证。

## 部署与存储

默认仅本机访问。SQLite 数据库位于 `data/records.sqlite`，含检验图像和签核信息，停服后可复制备份。可用 `PCB_DATA`、`PCB_HOST`、`PCB_PORT` 指定存储目录、绑定地址和端口。手机访问需将服务部署到可达的内网地址。浏览器实时摄像头与语音功能通常需要受信任的 HTTPS；手机亦可通过文件选择器拍照上传。系统采用姓名签核，部署至多用户网络前需配套身份认证与访问控制。
